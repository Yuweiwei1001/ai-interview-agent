## 项目一句话定位

**ai-interview-agent 是一个面向技术面试场景的智能多 Agent 面试平台**：候选人上传简历（可选 JD）后，系统自动生成面试计划，由多个“面试官 Agent”（技术基础 / 项目经验 / 编码能力）协同完成一场结构化、可持久化恢复的模拟面试；面试官可挂载自有知识库（RAG），出题与评分环节自动检索注入；最终输出带多维评分的面试报告与成长对比。

## 核心亮点速览

| 特性 | 说明 |
|:---|:---|
| 多 Agent 编排 | 基于 Spring AI Alibaba **StateGraph** 构建状态化、可编排的多 Agent 工作流（区别于单 Agent ReAct 循环） |
| 编程题全流程 | 力扣风格双栏编程页（题目面板 + Monaco 编辑器 + 可折叠结果面板）→ Docker 沙箱执行（直接执行透传 stdout）→ AI 动态测试用例 → 多维代码评估 → 挂起/恢复 |
| 人格行为策略 | 压力型 / 温和型 / 中性型三种面试官人格，影响评分严格度、是否重试、是否给提示、是否追问 |
| 长期记忆 | 每次面试评估的知识点落库（`knowledge_point`），下一场面试计划生成时注入薄弱点优先考察 |
| 知识库 RAG | 知识库/文档管理 + 异步向量化（ES 8 + text-embedding-v3），启动面试时可选挂载；出题与评分环节自动检索注入参考知识 |
| 评测体系 | golden 用例数据集 + 进程内驱动完整面试 + 规则指标（确定性回归门禁）+ LLM-as-Judge + 人工标注校准，报告落盘 `eval-reports/` 供版本对比，前端 `/eval` 页面可视化运行与报告 |
| LLM 可观测性与成本统计 | Spring AI Observation 自动埋点 → 每次 LLM 调用落 `llm_trace`（token/耗时/状态/估算成本/Prompt 摘录），按会话与 Agent 归因；轮次 traceId 串联同轮出题/检索/评分/追问，知识库检索落 retrieval span，评分按 traceId 回写，前端观测台可视化；含与主流观测方案（LangSmith/Langfuse/OTel GenAI）的差距对照与升级路线 |
| 结构化输出容错 | prompt 约束 + 防御性解析 + 业务兜底三层策略；解析失败走重试/降级，不造假数据（不注入假用例/降级分明示不可用） |
| 断点续面 | StateGraph Checkpoint 按 threadId（= sessionId）持久化到 MySQL，刷新页面 / 中断后可从断点恢复 |
| LLM 容错 | 统一的超时 / 重试 / 降级兜底机制，LLM 不可用时面试不中断（降级题库、规则评分） |
| 实时交互 | SSE 长连接推送题目/思考中/追问/报告就绪等事件，前端带轮询兜底防事件丢失卡死 |

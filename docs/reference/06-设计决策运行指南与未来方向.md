## 1. 关键设计决策与踩坑记录

> 均来自代码注释/演进历史，修改相关逻辑前务必阅读。

1. **文本评分必须用 LLM 真实评分**：历史的 `answer.length()*2` 长度启发式让长回答恒定满分，触发"连续 3 轮达标提前结束"，导致面试在编程题后直接终结。已移除提前结束特性，改用 `AnswerEvaluator`（LLM 评分 + 失败降级 60 分）。
2. **编程题路由不信任 LLM**：Coordinator 的 coding 决策有确定性护栏（最多 1 道、第 3 轮起、算法主题池、中后段强制安排）；CodingAgent 出题有系统设计关键词偏移检测 + 加强约束重试 + 题库兜底。
3. **挂起决策的唯一事实来源**：`waitingForCode` 必须在 EvaluateNode **节点体内**设置（而非条件边内），否则 `interruptBefore(codingRetryWait)` 挂起时外层无法感知挂起原因。
4. **结构化输出字段类型**：`InterviewPlan.AgentAssignment.topics` 必须用 `List<String>`（LLM 恒返回数组）；prompt 拼接用字符串而非 `.text()` 模板 + JSON 花括号（probe 验证过的坑）。
5. **轮次持久化双策略**：EvaluateNode 每轮增量落库（进行中刷新/重进不丢对话）+ 结束时整体重建（先删后插，幂等保证最终一致）。
6. **SSE 事件可能被静默吞掉**：无活跃连接时发送事件必须留日志；同时持久化 `current_question` + 前端轮询兜底，双保险防"提交后卡死"。
7. **ThreadLocal 上下文**：异步线程（interviewExecutor）内必须手动 `BaseContext.setCurrentId(userId)`，用完 finally 清除。
8. **手动结束不覆盖状态**：图完成流程前重新读取会话，若已被 endInterview 置为 interrupted 则跳过完成逻辑；手动结束也生成报告（有轮次时），避免前端无限等待。
9. **降级要诚实**：LLM/沙箱不可用的降级评分标记 `degraded=true`，重试提示明确告知"服务暂不可用，代码本身可能没问题"，防止误导候选人改正确代码。
10. **maxRounds 由计划决定**：PlanNode 将计划 `estimatedTotalRounds` 应用为 maxRounds（此前恒为 20，计划形同虚设）。
11. **Checkpoint 恢复类型兜底**：`InterviewState` 可能被反序列化为 `Map`，`toInterviewState` 用 Jackson `convertValue` 兜底。
12. **题号语义**：追问轮沿用所属主轮题号、编程题轮占题号（`distinctMainRounds` 计算），保证 SSE 题号连续且与报告一致。
13. **沙箱挂载**：编译阶段目录读写挂载、运行阶段只读挂载；`-i` 保持 stdin 注入测试输入。
14. **topic 硬校验**：Coordinator 决策的 topic 与已考察主题重复时替换为“综合技术”，防止 LLM 反复出同一主题变体题。
15. **知识库注入用确定性预注入而非 LLM 工具调用**：出题/评分前由代码显式检索并拼入 prompt，行为可预测、无额外 LLM 轮次开销；检索无结果/异常时返回 null 不阻断面试。
16. **qwen3.7-max 必须开 thinking**：该模型是混合思考模型，DashScope 强制 `enable_thinking=true`，application.yml 不配 `enable-thinking: true` 则所有 LLM 调用报 400（`The value of the enable_thinking parameter is restricted to True`）。
17. **密钥不入库**：DashScope api-key 写在 `application-local.yml`（.gitignore 忽略），application.yml 通过 `spring.config.import: optional:classpath:application-local.yml` 引入；环境变量 DASHSCOPE_API_KEY 仍可覆盖（优先级更高）。
18. **向量删除双保险**：删文档时同时按 kbId+docId 与 kbId+旧 title 两个表达式清理向量，防止历史 chunk 残留影响检索。
19. **观测埋点用 Spring AI Observation 而非 Langfuse/OTel**：项目规模下自建 `llm_trace` 表已够（成本/归因/会话链路），避免引入外部依赖；handler 全 try-catch + 异步限流写库，观测故障绝不影响面试主链路。
20. **观测归因必须跨线程传播**：`LlmCallWrapper` 每次调用新建单线程 executor，ThreadLocal 会丢——submit 前捕获 `LlmTraceContext` 快照并在执行线程内 set/finally clear；StateGraph 节点跑在图自己的线程池，需 `withTraceContext` 包装从 `InterviewState` 取 sessionId。新增 LLM 调用点必须传 agent 归因名，否则观测台 Agent 拆分缺失。
21. **actuator 的 Security 副作用**：引入 `spring-boot-starter-actuator` 会激活 `ManagementWebSecurityAutoConfiguration`，要求 `HttpSecurity` bean（项目关了 Security 自动配置），启动报 “required a bean of type HttpSecurity”——必须同步加入 `spring.autoconfigure.exclude`。
22. **成本重试诚实计费**：重试产生的多次 LLM 调用各自成行均计入成本（token 是真实消耗），不做去重美化。
23. **评测进程内驱动而非 HTTP/SSE 驱动**：EvalRunner 直接复用 `InterviewService.startInterview` + 轮询 `current_question` 提交回答，测的是真实核心链路（含图执行/评分/重试路径）；评测账号固定 testuser，sessionId 前缀 `eval-` 便于与真实会话隔离。
24. **评测驱动的代码提交以 DB 计数为事实来源**：coding 重试路径下状态持续保持 `waiting_code`（题目也可能不变），任何“状态离开才重置”的驱动标志都会导致第二次提交永不触发（实测卡死 12 分钟）；改为读 `coding_submission` 记录数决定提交第几份代码，且驱动需复刻 `CodingSubmitController` 的落库链路（`resumeCoding` 内部不写提交记录）。同理，规则指标的主轮统计必须按题面去重（重试同题多条记录），否则轮次/重复率失真。
25. **trace 默认存全文而非固定截断**：早期版本固定截 500 字导致调试时 prompt/回复看不全；现 `prompt-excerpt-length` 默认 -1 存全文，12000 字硬上限仅防 TEXT 列写入失败，生产想控表体积可配置为正整数。
26. **出题 prompt 成本瘦身**：八股题（TechnicalAgent）与算法题（CodingAgent）不再注入全量简历——主题已由面试计划 + Coordinator 决策保证，简历对这两类出题无增益（每轮省 ~2k 输入 token）；ProjectAgent 项目题必须保留全量简历（挖项目细节依赖它）。
27. **结构化输出三层策略**：prompt 约束 + 防御性解析 + 业务兜底（见 03 文档第 16 节）。解析失败不吞异常：AnswerEvaluator 主动抛出交由重试/降级，TestCaseGenerator 返回空列表不造假用例；后续可用 DashScope `response_format: json_object` 从解码层保证合法性。
28. **追问决策三层分工**：“是否追问”用确定性规则门控而非再调一次 LLM 决策：评分 agent（LLM）只提供事实分数，`FollowUpGenerator` 内按人格策略 + 阈值（ON_FAILURE 下 ≥60 不追问）做零成本 Java 判断，确认追问后才调 LLM 生成话术——控制流交给 LLM 有幻觉/循环风险且不可复现，规则门控也保证评测指标（追问触发率）可稳定度量。
29. **不用 LLM function calling / 不引入 Agent SDK**：全仓无 `@Tool`/`ToolCallback`，编排是确定性 StateGraph，LLM 只做内容生成不做行动决策（AskQuestionTool 只是图节点直接调用的普通 Bean）。对比市面 Agent SDK（OpenAI Agents SDK / Claude Agent SDK / LangGraph Platform 等将规划循环+工具+记忆打包为 `agent.run()` 的方案）：SDK 适合开放任务（开发快、自带观测），但自主循环不可精确控制轮次/成本/prompt，难调试且有厂商锁定；本项目是确定性业务流程，需要图挂起等代码提交、SSE 流式出题、评分降级这类深度定制，自研工作流在可靠性/成本/可评测性上更优；副作用是 trace 天然没有 tool span（见 03 文档 15.1）。
30. **观测三件套：轮次 traceId 串联 + 检索 span + 评分回写**：`CoordinatorNode` 派发新题时生成 `rt-*` 写入 State 并立即刷新线程上下文（否则节点内出题/检索拿到上一轮 ID），同轮出题/检索/评分/追问共享；`KnowledgeRetriever` 每次检索落 `kind='retrieval'` span（成本恒 0，汇总只统计 `kind='llm'` 行）；`EvaluateNode` 评分后按 traceId 异步回写 `eval_score`（写库队列改任务队列，保证 update 晚于同轮 insert）。选轮次级 ID 而非完整 span 树：改造成本最小且已覆盖“同轮调用关联 + 检索命中可观测 + 分数可归因”三大排障需求（见 03 文档 15.2/15.4）。
31. **前端默认模板类名必须与沙箱硬编码文件名对齐**：SandboxService 硬编码写 `Solution.java`（Java）/`solution.py`（Python），编程页默认代码模板必须是 `public class Solution`、编辑器文件标签须为 `Solution.java`/`solution.py`——否则默认模板点「运行」必然编译失败（`class Main is public, should be declared in a file named Main.java`）。前端任何模板/文件名改动需对照沙箱约定。
32. **运行反馈闭环：后端透传沙箱 stdout，前端区分空态**：`/api/coding/run` 无预设用例走直接执行分支时，若丢弃沙箱 stdout 只回 `results:[]`，前端结果面板会停在「点击运行」占位文案——运行成功但界面零变化，用户感知为“运行没用”。修复约定：TestRunResult 携带 stdout，前端控制台优先展示 error、其次 stdout；空态区分「未运行」与「已运行无用例」，运行结束无测试结果时自动切控制台 tab。

## 2. 运行与开发指南

### 2.1 环境要求

- JDK 21+、Maven、Node.js 18+、Docker Desktop（沙箱与 MySQL/Redis 容器依赖）。
- **Elasticsearch 8.13.4**（知识库向量库，端口 9200）：`docker run -d --name ai-interview-es -p 9200:9200 -e discovery.type=single-node -e xpack.security.enabled=false docker.elastic.co/elasticsearch/elasticsearch:8.13.4`；不启动 ES 时知识库功能不可用，但面试主链路不受影响（检索异常静默降级）。
- API Key（二选一，环境变量优先）：
  - 复制 `application-local.yml.example` 为 `application-local.yml` 填入 DashScope api-key（推荐，不入库）；
  - 或设置环境变量 `DASHSCOPE_API_KEY`（见 `.env.example`）。
- 其他环境变量：
  - `JWT_SECRET`：JWT 密钥（生产必改）；
  - `DB_PASSWORD`：MySQL 密码（默认 root123）。

### 2.2 启动步骤

```bash
# 1. 基础设施
docker compose up -d                     # MySQL(13307) + Redis(6380)
docker start ai-interview-es             # ES(9200)，知识库功能依赖（首次用上面的 docker run 创建）

# 2. 后端（首次会自动执行 Flyway 建表 + 沙箱镜像预热）
mvn spring-boot:run

# 3. 前端
cd frontend
npm install
npm run dev                               # 默认 5173，CORS 已放行
```

### 2.3 开发约定

- 面试核心逻辑改动集中在 `interview/graph/`、`interview/agent/`；新增节点需同时改 `InterviewGraphBuilder.buildGraph()` 与 `STATE_KEYS`，并用 `withTraceContext` 包装以保留观测归因。
- 新 Mapper 使用 MyBatis 注解（无 XML，`mapper-locations` 配置为预留）。
- LLM 调用一律走 `LlmCallWrapper.callWithRetry(agent, ..., fallback)`，不允许裸调（agent 参数同时承担观测归因）。
- 核心链路改动后用评测模块做回归：前端 `/eval` 页勾选用例发起（或 REST `POST /api/eval/run`，可 `skipLlmJudge: true` 只跑规则指标）→ `GET /api/eval/runs/{runId}`；报告 JSON 落盘 `eval-reports/`，与历史 run 对比 goalAchieved/跑题数/降级率等门禁指标。
- 涉及面试流程的改动建议参考根目录 `e2e-test.ps1` / `repro-*.ps1` 脚本做端到端回归。

## 3. 当前局限与未来方向

| 方向 | 现状 | 未来 |
|:---|:---|:---|
| Speaker 节点 | 占位透传（phase=TEXT 跳过） | Phase 2 数字人语音合成 |
| 知识库检索 | 固定 topK=3 + 阈值 0.5，仅出题/评分两点注入 | 追问/计划环节注入 + rerank + 阈值自适应 |
| 知识点归一化 | 最长公共子串相似度（预留 0.85 阈值语义） | 接入 embedding 余弦（可复用知识库向量能力） |
| 知识点抽取 | 关键词黑名单匹配 | 评估 prompt 结构化输出 + 管理端 verified 审核 |
| 报告 PDF | TXT 文本导出 | OpenPDF 生成真实 PDF |
| 沙箱 | Docker CLI 进程级调用、无容器池 | docker-java 客户端 + 常驻容器池（首包 <2s） |
| 可观测性 | 已落地 llm_trace：token/成本/会话链路 + 轮次 traceId 串联 + 检索 span + 评分回写（V8，前端观测台展示） | 图节点级 span 树、TTFT 流式指标、重试序号关联、Prompt 版本化；成本告警/预算上限；后续可升级 Langfuse / OpenTelemetry |
| 结构化输出 | prompt 约束 + 防御性解析 + 业务兜底 | DashScope `response_format: json_object` JSON 模式 / JSON Schema 强约束，从解码层保证合法性 |
| 评测 | golden 用例 2 个 + 规则/Judge/校准三层指标，报告落盘对比 + 前端 `/eval` 页可视化 | 用例扩充（MEDIUM 档位/多方向）+ run 对比接口 + CI 回归门禁 + 知识库检索质量评测 |
| 提前结束 | 已移除（评分失真） | 以真实评分为前提 + 最低轮次门槛恢复 |
| 面试超时 | 已实现：单题等待超时（默认 30 分钟可配）自动结束面试（状态 interrupted + 已有轮次生成报告），SSE 2 小时连接 + 15s 心跳保活 + 前端断线重连/轮询补偿 | coding 30 分钟未提交自动评估；定时任务清理僵死会话 |
| Redis | 仅容器就绪 | 缓存/限流/会话共享 |

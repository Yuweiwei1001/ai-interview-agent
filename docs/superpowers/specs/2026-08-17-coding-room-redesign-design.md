# 编程页面重构设计：力扣经典双栏风格

- 日期：2026-08-17
- 分支：`feature/coding-room-redesign`（worktree：`D:\IdeaProjects\ai-interview-agent-coding-redesign`）
- 状态：待用户审阅

## 背景

当前 [CodingRoomView.vue](../../../frontend/src/views/CodingRoomView.vue) 是「顶栏 + 题目折叠条 + 编辑器 + 右侧结果面板」布局，题目为纯文本粘贴展示，与主流 OJ（力扣/牛客）的做题体验差距较大：

- 题目长文本无结构（示例/约束不分区，靠 `max-h-40` 折叠条阅读）
- 结果面板常驻右栏，编辑器宽度被压缩
- 语言选择、运行/提交按钮在顶栏，与力扣习惯不符

## 目标

1. 重构为**力扣经典双栏布局**：左题目面板、右编辑器工作区，中间分隔条可拖拽
2. 题目面板升级为 **markdown 渲染 + 结构化增强**（示例/输入/输出/提示识别为卡片块）
3. 结果面板移至编辑器下方，**默认折叠、运行时自动展开**，以 Tab 组织（测试结果/控制台）
4. **零新增依赖**（naive-ui `NSplit` + `marked` 均已在项目中使用）
5. 交互逻辑完全不变：SSE 事件处理、`runCode`/`submitCode` API、路由跳转

## 非目标

- 不做难度徽章（后端未透传难度元信息，用户已确认放弃）
- 不做多题列表、题解、收藏、笔记等力扣附属功能
- 不修改任何后端代码
- 不新增编辑器功能（主题切换、快捷键、自定义输入等）
- 不改 `InterviewRoomView` 等其他页面

## 布局设计（桌面端 ≥ 768px）

```
┌────────────────────────────────────────────────────────┐
│ 顶栏: ← 返回 | 编程题 | [面试环节 3/3] | SSE 状态 ●     │
├─────────────────────┬──────────────────────────────────┤
│ 题目面板 (42%)       │ 编辑器 Tab 条: Main.java | Java▾ │
│                     │                [▷ 运行] [提交]    │
│ 1. 题目标题          ├──────────────────────────────────┤
│ 正文（markdown）     │                                  │
│ ┌ 示例 1 ─────────┐ │  Monaco 编辑器 (vs-dark, 撑满)    │
│ │ 输入：…  输出：… │ │                                  │
│ └─────────────────┘ │──────────────────────────────────┤
│ 提示/约束（卡片）    │ ▼ 结果面板（默认折叠，运行时展开）  │
│         ║可拖拽分隔条 │ ✓ 通过 2/2 · 100%                │
│                     │ [测试结果] [控制台]                │
└─────────────────────┴──────────────────────────────────┘
```

### 顶栏

- 保留 `BackButton`（返回 /home，现有组件）
- 标题「编程题」+ 徽章「面试环节 3/3」（面试编排固定为八股→项目→编程收尾，编程恒为最后一题，徽章静态文案）
- 右侧新增 SSE 连接状态指示（已连接 ● / 连接失败 ●）；连接失败时同时置 errorMsg（仍显示在结果面板顶部警告条）
- 运行/提交按钮**不在**顶栏（移至编辑器 Tab 条）

### 左：题目面板

- 面板头部：题目标题（从题目文本提取，见「题目渲染」），下方细分隔线
- 正文区：可滚动，marked 渲染 + 结构化增强
- 窄屏时整个面板折叠为「题目 ▶」手风琴头（沿用现有交互习惯）

### 右：编辑器工作区

- **Tab 条**（深色 `#1e293b`，与编辑器一体）：
  - 文件名标签：随语言切换 —— `java → Main.java`、`python → main.py`
  - 语言下拉（`NSelect`，现有 Java/Python 选项）
  - 右侧：`▷ 运行`（描边样式，loading 态转圈）+ `提交`（绿色实心，loading 态转圈）
- **Monaco 编辑器**：vs-dark 主题、撑满剩余空间、无边框圆角（`CodeEditor` 组件样式微调，仅此组件的调用方是本页面）
- **结果面板**：见下节

### 结果面板（编辑器下方）

- **默认折叠**为一条细条（「执行结果 ▶」）；以下情形自动展开：
  - 点击「运行」发起时
  - 收到 SSE `WAITING_CODE` 重试提示时
  - 出现错误（SSE `ERROR`、运行/提交失败）时
- 展开后头部：状态行（`✓ 通过 x/y · 通过率 z%` 或 `✗ 未通过` / 空态）+ Tab + 收起按钮
- 两个 Tab：
  - **测试结果**：n-progress 通过率条 + 用例卡片列表（✓/✗、用例名、`动态` 标签、详情），沿用现有数据结构
  - **控制台**：黑底输出（`data.error` / 异常 msg），等宽字体
- 重试提示（`WAITING_CODE`）与错误提示以 `NAlert` 显示在面板体顶部（两个 Tab 均可见）

## 题目渲染

输入：`route.query.question`（LLM 生成的 LeetCode 风格纯文本，非保证 markdown）。

处理管线（`QuestionPanel.vue` 内实现，纯前端、无新依赖）：

1. **标题提取**：取首行；若含「：」或「.」分隔且长度 ≤ 40 字，取分隔前部分为标题（如「两数之和：给定…」→「两数之和」）；否则首行 ≤ 30 字整行作为标题；再否则标题为「编程题」，首行并入正文
2. **结构化预处理**：按行扫描，识别以下模式并包裹为 HTML：
   - `示例 N` / `示例N` / `Example` → 小节标题（加粗）
   - `输入：`/`输出：`/`解释：`/`返回：` 行 → 归组进浅色卡片块（`<div class="q-sample">`），键值分行渲染
   - `提示`/`约束`/`数据范围`/`进阶` → 小节标题，其后内容为列表/普通段落
   - markdown 语法行（代码块 ```、`**`、列表等）→ 保持原样交给 marked
3. **marked 渲染**：`marked.parse(text, { breaks: true, gfm: true })`（与 ChatBubble 一致的配置），对输出做 DOMPurify 级别的安全性不做额外处理（内容来自自家 LLM，与 ChatBubble 同等信任级别）
4. **样式**：题目正文使用 prose 风格手写 CSS（不引入 @tailwindcss/typography），示例卡片浅灰底圆角，`code` 行内代码灰底

兜底：任何无法识别结构的文本按普通段落渲染，不破坏原文。

## 响应式（< 768px）

- 顶栏保持
- 题目面板折叠为手风琴头（默认收起，点击展开，max-h 限制滚动）
- 编辑器固定高度 `55vh`
- 结果面板跟随编辑器下方（同样默认折叠）
- 不渲染 NSplit 拖拽（纵向自然堆叠）

## 组件划分

| 文件 | 职责 | 变更类型 |
|---|---|---|
| `frontend/src/views/CodingRoomView.vue` | 布局骨架、NSplit 分栏、SSE、运行/提交状态管理 | 重写 |
| `frontend/src/components/QuestionPanel.vue` | 题目标题提取 + 结构化预处理 + marked 渲染 | 新增 |
| `frontend/src/components/CodingResultPanel.vue` | 结果面板：折叠状态、Tab、通过率、用例列表、控制台、提示条 | 新增 |
| `frontend/src/components/CodeEditor.vue` | 去除外边框圆角（新增 `bare` prop，默认 false 保持向后兼容） | 微调 |

状态归属：
- `code`、`language`、`running`、`submitting`、SSE 相关（`retryHint`/`errorMsg`）→ CodingRoomView（不变）
- 面板折叠、当前 Tab → CodingResultPanel 内部状态；通过 `watch(retryHint/errorMsg)` + props 变化自动展开
- 左右分栏比例 → NSplit 非受控默认 42/58（不做持久化）

## 不变项（回归保障）

- SSE 事件处理逻辑：`WAITING_CODE`/`QUESTION`/`FOLLOW_UP`/`COMPLETE`/`REPORT_READY`/`ERROR` 分支行为逐一保留
- `runCode`/`submitCode` API 及提交成功后跳转报告页的时序
- `submitCode` 携带的 `question` 参数（`route.query.question` 原文）
- Monaco 编辑器配置（fontSize、tabSize、wordWrap 等）

## 验收标准

1. `npm run build`（vue-tsc）编译通过
2. 桌面端：左右分栏可拖拽调整比例；题目面板滚动正常；编辑器随窗口 resize 自动重排
3. 点击「运行」：结果面板自动展开、显示通过率与用例；「控制台」Tab 可切换查看输出
4. 收到 `WAITING_CODE`：结果面板自动展开并显示警告条
5. 窄屏（<768px）：纵向堆叠可用，题目手风琴可展开收起
6. 文件名标签随语言切换（Main.java / main.py）
7. 端到端：走完一次完整面试（八股→项目→编程），编程页各 SSE 分支（重试挂起→修改→提交→报告页）表现与重构前一致

## 测试计划

- 现有项目无前端单测基础设施，本重构以**手动端到端验证**为主
- 验证路径：启动 Docker（MySQL/Redis）→ 后端 → 前端 dev server → 登录 testuser → 发起面试 → 进入编程环节 → 运行/提交/重试各分支
- 辅助检查：浏览器 console 无报错；vue-tsc 零错误

## 风险与权衡

- **题目文本结构不稳定**（LLM 输出格式漂移）：预处理规则宽松匹配 + 原文兜底，最坏情况退化为纯 markdown 渲染，不会丢内容
- **NSplit 嵌套滚动**：Monaco `automaticLayout: true` 已有；结果面板内部滚动独立，无冲突
- **移动端触控拖拽**：窄屏不渲染 NSplit，规避触控拖拽体验问题
